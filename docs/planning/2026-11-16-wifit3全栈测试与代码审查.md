## 3. 阻断项（9 条，去重后）

### B1 产品级 E2E 链路整段缺失（系统与验收，最严重）

`use_sim_backend()` 全仓只有 2 个调用点（`tests/chips/sim/test_driver.py:133`、`:144`），均不在 `tests/ui/` 下。而真正的"产品路径"测试 `_array_with_sim()`（同文件 `:35-42`）是手工拼装的：

```python
driver = SimulatedDriver()          # 直接 new，绕过 manager.devices()
array = WlanArray()                 # 直接 new
iface = array.attach(WlanInterface(driver, "wlan0", "SIM80211"))
```

即：发现层 → 后端 → 驱动 → `WlanArray` → UI 这五段从未在同一进程内首尾相连过一次。三位专家从不同角度独立命中同一事实（白樾从 UI 侧、柯砚从 bringup 侧、苏雅从覆盖侧）。无 `.feature`、无 Gherkin、无验收文档。

**本项是本次交付最实质的缺口**：虚拟适配器的存在意义就是让产品链路可以无硬件跑通，而当前它只服务于单元测试。

### B2 14 个 `slow` 测试在 CI 中永不执行

`pyproject.toml:71`：

```toml
addopts = "--import-mode=importlib -m 'not slow'"
```

`pyproject.toml:73` 自述 slow = `heavyweight end-to-end WEP crypto proof; deselected by default`。被排除的 14 个测试中包含**整个仓库唯一的 WEP 密钥恢复证据** `tests/campaigns/test_wep_campaign.py:109`。

这不是"测试缺失"，是"证据链在 CI 里断开"：核心解密能力（WEP）的端到端证明不在门禁内，回归时无人会发现它坏了。

### B3 全局可变状态无兜底复位

`set_usb_backend_factory` 是进程级全局单例。当前 2 个调用点确实用 `try/finally` 正确复位（`:134-137`、`:145-150`），所以**当下无泄漏**。但：

- 无 repo 级 `autouse` 夹具兜底，任何后续测试忘记复位就会污染整个 session；
- `reset_usb_backend()` 的复位**结果无任何断言**，无法证明复原真的生效。

严重度由"当前已泄漏"降为"结构性风险"，理由见第 4 节 X4。

### B4 违规路径零覆盖 + 静默回退

`src/wifit3/wlan/array.py:168-175`（注意：不是柯砚写的 `device/array.py`，该文件不存在）：

```python
target = iface
if target is None and channel is not None:
    target = self.select_iface(channel)
if target is None:
    target = self._members[0] if self._members else None   # :172-173
if target is None:
    raise RuntimeError("no interface available to lease")
```

docstring 写的是 "raises when no interface can serve"，但实际行为是：指定了 `channel` 而 `select_iface()` 返回 None（没有卡能到该频段）时，**不抛错，静默取第一张卡**。于是 5 GHz 目标的 campaign 会在一张只支持 2.4 GHz 的卡上发帧。

`lease()` 的三条违约分支（无卡、频道不可达、iface 与 channel 冲突）全部零覆盖。

### B5 `Lease.__aexit__` 无异常隔离

`src/wifit3/wlan/lease.py:71-77`：

```python
async def __aexit__(self, *exc) -> bool:
    if self._ack_tally:
        await self.iface.disable_rx_acks()      # 拔卡时这里抛异常
    await self._exit_active_monitor()           # 之后全部不执行
    if self._channel is not None and self._orig_channel is not None:
        await self.iface.set_channel(self._orig_channel)
```

三步串行无 `try/finally`。租约期内拔卡时，`disable_rx_acks()` 抛异常会让 own-MAC 从 array 的登记表里永久泄漏、频道不还原。清理路径恰恰是最需要抗异常的地方。

### B6 虚拟适配器不发 ACK，deauth 恒报 `acks=0`

这是本次新增代码中的一个**功能性假阴性**，主理人已复现确认。

`src/wifit3/chips/sim/radio.py:128-148` 的 `handle_tx()` 只在 subtype 11（Auth）和 0/2（Assoc/Reassoc Req）时返回帧，其余一律 `[]`。而 deauth 是 subtype 12，因此：

1. `VirtualRadio.handle_tx()` 对 deauth 返回 `[]` → 无帧进 RX 通道；
2. `SimulatedDriver._deliver()` 不被调用 → `record_ack()` 不被调用；
3. `wlan/interface.py:275` 无条件写 `DeauthResult(measured=True)`，两方向 acks 均为 0；
4. `ui/screens/focus_v2/screen.py:1195` 打印 `0/N de-auths ACK'd (silent AP & client)`。

结果是：**在模拟器上，deauth 永远被判定为"AP 和客户端都静默"**。而 `SimulatedDriver.FAKE_MAC = FakeMacSupport.SPOOFABLE` 又宣称这张卡能伪造 MAC，两者叠加会教出错误结论。凡是基于 sim 演练 deauth 策略的路径，拿到的都是与真实空口相反的信号。

顺带两个同源缺陷：
- **无 Probe Response**：`radio.py` 里根本没有 subtype 5 的构造器，主动扫描（probe request）通路在 sim 上完全无应答，只有被动 beacon 可用。
- **Reassoc 回应错配**：subtype 2（Reassoc Req）收到的是 `assoc_resp()`（subtype 1），协议上应回 Reassoc Response（subtype 3）。

### B7 自研核心 9 包无强制覆盖率门槛

`README.md:480-484` 仅"建议"覆盖率，`pyproject.toml` 无 `--cov-fail-under`。9 个包（`wlan` / `campaigns` / `dot11` / `device` / `ui` / `crack` / `persist` / `vault` / `setup`）全部无门禁约束，新增代码可以无限稀释既有覆盖。

### B8 手改变异实验：20/20 存活

苏雅对 sim 三模块做了 20 处手工植入变异（改坏实现 → 跑测试 → 还原），**全部未被测试发现**。主理人复核了其中的关键几条，确认属实：

- `radio.py:81` `secured` 恒返回 `True` → 全绿。实测：`VirtualAccessPoint.secured` 在 `src/` 和 `tests/` 中**零引用**，是纯死代码。
- `radio.py:41-43` `pmkid_kde` 前缀 `b"\xdd\x14..."` 被改坏 → 全绿（但苏雅对该行的描述有误，见 X2）。
- 边界常量与分流分支类变异多数存活，说明断言强度弱于覆盖数字所暗示的水平。

**20/20 存活比 74.3% 的覆盖率更值得警惕**：覆盖率证明代码被执行过，变异存活证明执行过也没人检查结果。

## 4. 对专家结论的复核与更正

三位专家的报告并非全部可直接采信。主理人逐条对齐代码后，有 4 条需要修正，另外确认了 2 个既有 flaky 与本次改动无关。

### X1 苏雅：`_NON_CNVI_USB` 符号不存在（驳回）

原话称 `device/host_radios.py:230` 的 `_NON_CNVI_USB` 需要永假分支。全仓 grep 无此符号。`host_radios.py:230` 实际是 `render()` 的空列表返回语句。**该条驳回**，但其指向的"空列表分支零覆盖"是真的，已并入上表 P4。

### X2 苏雅：`radio.py:81` 描述与代码不符（部分驳回）

原话称该行是 `pmkid_kde` 中的 `if value[:1] != b"\xdd"` 强制改写逻辑。实际 `:81` 是 `return self.akm is not None`（`secured` 属性）；`pmkid_kde` 在 `:41-43`，无任何条件分支。

**变异实验本身有效**（`secured` 恒真存活），但代码描述是错的。合并后结论加强而非削弱：`secured` 是零引用死代码。

### X3 柯砚：`array.py` 路径错误（更正）

原文写 `src/wifit3/device/array.py:172-173`。该文件不存在，`WlanArray` 在 `src/wifit3/wlan/array.py:42`，`:172-173` 行号正确。结论成立，路径已更正为 B4。

### X4 柯砚：`pin.py` 缺 `iface` 早退（降级）

原文称 `campaigns/pin.py:479-481` 缺少 `campaigns/pbc.py:69-70` 才有的 `if self.iface is None` 早退，属 P2 缺口。

核实后**降级**：该守卫在框架层集中存在，`campaigns/campaign.py:76-79`：

```python
if self.array is not None and self.iface is None:
    logger.warning("campaign %r: no card can reach channel %s; aborting", ...)
else:
    await self._loop()
```

`_loop()` 根本不会在 `iface is None` 时被调用。`pbc.py` 自己的守卫是局部冗余防御（因为它显式传 `iface=self.iface` 给 `lease()`）。

**但这次降级反而暴露了真正的问题**：`pin.py:478` 调用 `lease(channel=..., ...)` 时**不传 `iface`**，把选卡完全交给 `select_iface(channel)`，而这个函数返回 None 时会踩到 B4 的静默回退。所以 `campaign.py` 的中央守卫挡不住这条路径 —— 真正的缺口在 B4，不在 pin.py。

## 7. 整改路线建议

按"阻断程度 × 整改成本"排序，前三批可在不依赖产品决策的前提下推进：

### 第一批：修 B6（虚拟适配器假阴性）—— 唯一的功能性缺陷

`VirtualRadio.handle_tx()` 应按 802.11 真实行为补链路层 ACK：单播 MPDU 在信道上被收到即回 ACK（FC = `0xD4`，RA = 原帧的源地址 `frame[10:16]`），广播/组播不回。这样 `record_ack()` 才能收到 RA 命中 `_our_tx_macs` 的帧。

连带补：
- Probe Response（subtype 5）构造器，打通主动扫描通路；
- Reassoc Req（subtype 2）改回 Reassoc Response（subtype 3）；
- 删除零引用的 `secured` 属性。

**验证方式**：新增测试断言 `deauth_client()` 在 sim 上返回 `acks > 0`，且广播 deauth 仍为 0。

### 第二批：修 B4 + B5（租约契约与清理路径）

- `array.py:168-175` 拆开两种情形：`channel` 已指定但 `select_iface()` 返回 None → `raise`；`channel` 为 None → 保留 `members[0]` 回退。
- `lease.py:71-77` 三步清理各自包 `try/except`，保证 own-MAC 注销与频道还原在任何一步失败时仍执行。
- 补 3 条违约分支测试。

### 第三批：补覆盖与变异防线（B7、B8）

- `pyproject.toml` 增加 `--cov-fail-under`（自研 9 包独立门槛，`chips/` 除外）。
- 补 `probe_windows` / `probe_linux` / `main()` 的分支测试（当前 117 / 45 行零覆盖）。
- 把 20 个存活变异体里价值最高的 5-8 个转成断言（优先 `pmkid_kde` 前缀、边界常量、分流分支）。

### 第四批：补 E2E 与 CI 闸门（B1、B2、B3）—— 需产品决策

- 用 `use_sim_backend()` 串起 `manager.devices()` → `manager.wlan_iface()` → `WlanArray` → UI 的一条最短旅程，替换 `_array_with_sim()` 的手工拼装。
- 增加 repo 级 `autouse` 夹具复位 `set_usb_backend_factory`，并断言复位生效。
- `slow` 测试的去留按决策 3 执行。

## 8. 结论

本次交付的 1274 行生产代码，**单元层面测得 74.3%-96.9% 行覆盖，但 20/20 变异体存活**，说明断言强度跟不上覆盖率。更关键的是三条结构性缺陷：

1. 虚拟适配器不发 ACK，使 deauth 在 sim 上恒报"双方静默"（B6）—— 这是唯一的功能性错误，且恰好位于本次交付的核心价值主张上；
2. 产品级 E2E 从未组装过一次，`_array_with_sim()` 是手工拼装而非产品路径（B1）；
3. WEP 端到端证据在 CI 中永不执行（B2）。

这三点叠加的后果是：**当前测试套件能证明"每个零件单独转过"，不能证明"整机跑得通"**。虚拟适配器本应解决后者，但它目前只被用在前者。

建议按第四批依赖顺序推进：先修 B6（无外部依赖，1 个文件），再修 B4/B5（核心契约，需决策 2），然后补覆盖防线，最后在决策 1 和 3 落定后补 E2E 与 CI 闸门。
